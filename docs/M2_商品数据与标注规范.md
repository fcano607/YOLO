## 2. 照片怎样变成训练数据

**原始照片 → YOLO 提议框和轮廓 → 人工确认商品类别、修边界、补漏检和删误检 → 审核标签 → 检查加载 → 后续 M3 微调。**

现有 YOLO 可以提供轮廓草稿，即使预测的通用类别不对，也可以在轮廓正确且经人工核实时复用。它不认识新商品名称；奶盒可能完全漏检，需要手工补画。不能把整个 COCO 的 cup / bottle 类统一改名。

草稿保留原预测类别、分数和来源，供检查；标准训练标签只写新商品 ID 和多边形坐标，不写置信度。把预测分数改成 1 不会修正类别或轮廓，也不能替代人工审核。

拍摄保存未涂画的原图，预测框、文字和彩色掩膜只用于复核。标注中间文件与训练标签分别保存，避免把未经检查的草稿送进训练。

## 3. 首版轮廓标注规则

| 情况 | 如何处理 |
| --- | --- |
| 奶盒 | 沿整个包装的可见外轮廓标注，包含盒身、封口和连接着的盒盖 |
| 瑞幸杯 | 杯身、装在杯上的杯盖及贴合杯身的杯套视为同一个包装实例 |
| 杯套有 / 无 | 商品类别相同；当前实物有杯套，去掉杯套的照片若纳入数据，需记录并检查可见识别信息 |
| 吸管、手、桌面、阴影、倒影 | 不并入包装掩膜；分离的杯盖 / 杯套不作为新的瑞幸杯实例 |
| 透明杯 | 按包装整体的可见外轮廓标注，不单独分割液体或在透明杯内部挖背景孔洞 |
| 同类多个实物 | 每个实物分别标一个实例；目前只有一个实物时，不通过复制图像假装增加真实实例 |
| 两种或三种商品同框 | 逐实例确认类别并标齐，不因其他目标难画而遗漏 |
| 轻微遮挡 | 类别有可见区分依据，且剩余可见轮廓连通时，只标可见区域，不补出被挡住的部分 |
| 严重遮挡、无法区分类别 | 首批整张图片暂不纳入监督训练，记录原因；不能删掉目标标签后当背景图 |
| 轮廓多处断开、存在复杂孔洞 | 首批单独放置，待标注工具与转换验证后再纳入；不把同一物体拆成多个假实例 |
| 其他杯、奶盒、手机等非目标 | 不标为这三类；若图片中没有任何目标商品，建立空标签 |
| 真正的空桌面 | 空标签；有目标却漏标的图片不是负样本 |

这是本项目首版约定。只标 Logo 会把“包装分割”变成“Logo 区域分割”，所以不采用。包装缺乏可见区分信息的背面、严重模糊画面等先单独放置，不能仅凭它摆在左边或右边来给模型提供区分类别的依据。

辅助结果逐图审核：图里有几个目标、类别是否对、是否漏标或重复、轮廓是否包进桌面 / 手、是否遗漏包装边缘。原模型没检出时仍要补标。

## 4. 标签保存成什么格式

每张原图对应一个同名 `.txt`，每个实例一行：

```text
class_id x1 y1 x2 y2 x3 y3 ... xn yn
```

坐标按原图宽高归一化：`x_norm=x/W`、`y_norm=y/H`，每个多边形至少三个顶点。例如 640×480 原图上的点 (320,240) 对应 (0.5,0.5)。检测框的五列格式不能替代分割轮廓。

完整图中的所有目标都要有标签；确认没有这三类目标时使用空文件。审核者或分数等元数据单独登记，不附加在训练标签行末。

格式依据：[Ultralytics 分割数据格式](https://docs.ultralytics.com/datasets/segment/)。已核对本项目锁定的源码：[分割结果导出](../third_party/ultralytics/ultralytics/engine/results.py)、[标签加载检查](../third_party/ultralytics/ultralytics/data/utils.py)。`save_txt(save_conf=False)` 可参考，但直接导出的 COCO 类别仍需改成商品 ID，轮廓仍需审核；后续导出不能追加重复行或带入跟踪 ID。

## 5. 你需要做什么

本轮类别登记已使用你提供的信息完成，不需要再查厂家资料。后续试标需要你提供原始画面，并确认各包装和轮廓；脚本、模型运行、格式转换和质量检查由助手继续落实。

| 你的操作 | 为什么需要 |
| --- | --- |
| 准备三种现有实物 | 为照片中的商品身份提供真实依据 |
| 拍清正面和斜侧面，记录是哪一种 | 留下包装参考，也检查模型是否能抓到轮廓 |
| 在两个不同背景里都拍到三类 | 避免某一类总和某一个背景绑定 |
| 挪动位置、改变距离和角度 | 检查同一个包装在不同画面中的表现 |
| 核对类别和轮廓，指出漏检 | 让模型草稿成为真实训练标签 |
| 保存原图，保留拍摄场次 | 后续按组划分，避免近重复帧跨集合 |

可用现有摄像头或手机，使用正常照片清晰度，保存原图即可；不需要你手工缩放到 640×640、计算坐标或把置信度改成 1。

### 本次审核如何操作

20 张合并审核服务已启动，本次页面为 [本地商品轮廓审核](http://127.0.0.1:58308)。重新启动时会自动选择空闲端口，以终端打印的 URL 为准。

1. 在右侧选择商品类别。选中可用草稿后点“指定类别”；不要依照 book / phone / vase 原类别决定商品身份。
2. 没有草稿时点“补画漏检”，沿可见外边缘逐点点击，按 Enter 完成。原图仍按原分辨率保存，不需要自己计算归一化坐标。
3. 点击轮廓或列表选择实例，拖顶点修边界；点“简化选中轮廓”可减少密集顶点，再检查边界。删掉桌面等非目标；误操作可以撤销。
4. 逐图检查所有目标，勾选人工确认，再“保存并下一张”。没有目标必须明确选择空背景；身份或边界难判断时选择“暂不纳入”并填写原因。
5. 补画 / 简化后检查完整包装，尤其是连接盖、杯盖及套；不要并入阴影。严重遮挡或裁切到无法辨认时先排除整图，不以空标签代替。

模型草稿在 `annotations/drafts/`。只有明确确认后才写 `annotations/reviewed/<image_id>.json` 和同名分割 `.txt`；后者只含商品 ID 与归一化多边形，不含分数。排除图只存理由，不写标签；反复保存替换结果，不追加重复行。原始图片哈希改变、未分配商品类别、越界 / 非有限 / 自交 / 退化多边形会拒绝导出。

### 自交保存问题怎样解决

在第二批第 5 张（合并第 11 张）保存时，页面报 `Polygon intersects itself`。捕获实际失败请求发现是第 1 条瑞幸杯手画轮廓，另外两条奶盒合法；26 点杯轮廓的末尾点距起点约 3.3 原图像素，闭合边出现小交叉。将问题缩到仍自交的 4 个点，先得到失败测试，再修复保存流程并通过回归；用户最终修正该杯轮廓后已正常保存。

修复范围：手画轮廓若因末尾近起点而不合法，且移除距起点 5 原图像素内的末尾点后通过校验，可只移除这个多余闭合点，元数据记录 `geometry_cleanup`；真正自交仍拒绝，错误指明商品 / 轮廓序号 / 两条交叉边。新版页面点回起点直接闭合，Enter 结束也不需额外闭合点。失败保存会备份为 `annotations/in_progress/` 的未审核工作稿，恢复后仍需确认；成功后移除工作稿，错误标签不会进入训练。页面另有本地未保存修改缓存。调试输出已移除。
