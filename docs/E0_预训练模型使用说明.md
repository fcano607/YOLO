权重 6,182,636 字节，SHA256 为 `55ed65c56c91713d23e8402371c6c49a6fd84f257f7dce452e8d70e41dcbe152`。这个哈希由本次官方下载计算，用于后续复现检查；GitHub 对该旧资产没有提供独立 digest。

E0 保留 COCO 80 类输出，仅在推理时筛选三类。脚本通过实际 `model.names` 查找类别，不直接假设项目 ID 等于预训练模型 ID。

| 名称 | 项目 ID，后续三类数据使用 | 当前 E0 模型 ID |
| --- | --- | --- |
| cup | 0 | 41 |
| bottle | 1 | 39 |

参数统一保存在 [configs/e0.yaml](../configs/e0.yaml)：640×640 固定输入、FP32、GPU 0、conf=0.25、NMS IoU=0.7、retina_masks=true。当前锁定版本使用 `quantize=32` 表示 FP32。这些是本次演示参数，不是经过验证集优化后的选择。

## 2. 准备资产

在项目根目录运行：

```powershell
conda activate yolo
python scripts/prepare_e0.py
```

脚本校验已有权重；缺失时按固定 URL 下载并核对字节数和哈希。同时从锁定源码复制 `bus.jpg` 作为通用检查图，不安装或升级依赖。

## 3. 运行图片、视频和摄像头

通用图片测试，显示全部 80 类：

```powershell
python scripts/predict_e0.py --source demo/input/E0/bus.jpg --all-classes
```

桌面图片，默认只显示项目三类：

```powershell
python scripts/predict_e0.py --source runs/E0/M0-04_20261002_camera_targets/input_best.jpg
```

已保存的视频：

```powershell
python scripts/predict_e0.py --source runs/E0/M0-04_20261002_camera_targets/input.mp4
```

摄像头采集约 10 秒，保存输入与分割结果：

```powershell
python scripts/predict_e0.py --camera --seconds 2
```

显示预览窗口，按 Q 或 Esc 提前停止；`--seconds` 到期也会退出：

```powershell
python scripts/predict_e0.py --camera --seconds 30 --show
```

摄像头使用已通过本机检查的 DSHOW / 索引 0，不强制更改摄像头分辨率或 MJPG 设置。先完成 GPU 初始化再开启摄像头；画面处理在单循环中完成。整个摄像头运行放在有超时限制的子进程中，驱动阻塞时保存失败记录并终止该任务的工作进程。输入视频和摄像头画面会保存到输出目录。

| 参数 | 用途 |
| --- | --- |
| `--source <路径>` | 图片或视频路径，相对路径从项目根目录解析 |
| `--camera` | 使用本机摄像头，与 `--source` 互斥 |
| `--all-classes` | 显示原模型全部类别，不筛选三类 |
| `--seconds 10` | 限制处理时间；摄像头默认 10 秒，文件视频默认读完 |
| `--max-frames 100` | 限制视频或摄像头处理帧数 |
| `--camera-index 0` | 选择摄像头索引 |
| `--show` | 显示预览窗口 |
| `--device cpu` | 切换设备；本次验收使用 GPU 0，CPU 命令尚未运行验收 |
| `--conf 0.25` | 改变显示阈值，报告保留实际参数 |
| `--output runs/E0/<新名称>` | 指定新输出目录；已有目录拒绝覆盖 |

## 4. 每次运行保存什么

默认保存到 `runs/E0/<时间戳>/`：

| 文件 | 内容 |
| --- | --- |
| `summary.json` | 模型、实际设备、版本、类别映射、参数、帧数及退出 / 释放状态 |
| `frames.jsonl` | 每帧框、置信度、类别、非空 mask 面积、输出 shape / device |
| `input_first.jpg` / `result_first.jpg` | 第一帧输入与可视化 |
| `input_best.jpg` / `result_best.jpg` | 本轮预测框数量最多的示例帧；文件名不表示精度最好 |
| `best_frame.json` | 上述示例帧的预测数值 |
| `input.mp4` / `result.mp4` | 视频 / 摄像头的输入与可视化；单张图片运行不生成视频 |
| `worker.log` | 摄像头工作进程日志；超时另存部分标准输出与错误 |

视频使用 MP4 容器 / mp4v 编码，已实际重新解码核对帧数。本机摄像头报告帧率为 0，录制采用配置中的 30 FPS 回退值；文件时间轴由录制 FPS 决定，不保证与墙钟完全一致。GIF 演示预览是从结果视频抽帧得到的，完整视频保留在 run 中。

运行成功返回退出码 0，失败返回 1；参数错误或已有输出目录等错误以终端提示为准。`passed` 表示输入读取、预测、输出保存和正常退出成功，识别正确性需要逐例核对。

## 5. 本次能说明什么

已验证预训练权重可在本机 GPU 上执行，框与 mask 输出在 cuda:0，三种输入可处理并保存，摄像头正常释放。公开测试图不是项目精度测试集，自采的 10 秒视频也没有正式逐帧标注。框的 confidence、出现次数和示例帧不能替代 Precision、Recall 或 mAP。

本次观察到右侧手机和杯子的预测、左侧遮挡手机的漏检，以及右侧瓶子的漏检 / 误分类。后续数据采集应覆盖遮挡、完整入镜和物品外观变化，再用冻结数据划分比较 E1/E2/E3。

M0-05 已完成固定输入 FP32 ONNX 导出、ORT CPU/CUDA 执行与 TensorRT 构建 / 执行，见[部署预检查报告](../reports/deployment/M0-05_部署兼容性预检查.md)。安装部署依赖后 E0 图片回归通过；下一项 M0-06 保存完整可复现环境及命令。
