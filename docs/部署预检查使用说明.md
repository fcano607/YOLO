# M0-05 部署预检查使用说明

这是环境兼容性检查入口。它导出 E0 ONNX，保存同输入 PyTorch 参考输出，分别实际执行 ORT CPU、ORT CUDA 与 TensorRT；完整独立后处理在 M5/M6 实现。结果见[验收报告](../reports/deployment/M0-05_部署兼容性预检查.md)。

## 1. 本机复查

从项目根目录运行：

```powershell
conda activate yolo
python scripts/check_deployment.py
```

也可用 `D:\software\anaconda\envs\yolo\python.exe` 的绝对路径。入口按顺序启动四个限时工作进程；export 300 秒，ORT CPU/CUDA 各 120 秒，TensorRT 600 秒。日志持续写入文件，控制终端打印阶段和退出码。

只复查某一项：

```powershell
python scripts/check_deployment.py --stage export
python scripts/check_deployment.py --stage ort_cpu
python scripts/check_deployment.py --stage ort_cuda
python scripts/check_deployment.py --stage trt
```

后三项依赖已生成且哈希一致的 ONNX 和参考数组；修改输入或导出配置后，应重新运行全部阶段。单项 exit code 0 只说明该项通过；检查全部阶段需要汇总 JSON 中 `all_backends_passed=true` 和 `same_artifacts_verified=true`。

## 2. 输入、配置与输出

配置：[configs/deploy-precheck.yaml](../configs/deploy-precheck.yaml)。当前固定 E0 权重、640、FP32、batch=1、opset17、无内置 NMS；输入引用 M0-04 已保存的公交车图和桌面图。因此新副本需恢复这两张图，或在配置中指定本机图片后重新生成参考。

- `artifacts/precheck/M0-05/`：权重副本、ONNX、原生 engine、每张图的输入/参考/后端输出数组，以及 ORT profile。大型文件不纳入 Git。
- `logs/deployment/M0-05_export.json`：模型参数、接口、原始图片与张量哈希。
- `logs/deployment/M0-05_ort_cpu.json`、`M0-05_ort_cuda.json`、`M0-05_trt.json`：实际执行及逐输出数值对照。
- `logs/deployment/M0-05_summary.json`：各阶段结果与产出一致性。
- 同目录 `.log`：阶段运行与构建日志；首次中文路径失败另存 `M0-05_trt_attempt1_unicode.*`。

重复运行会更新该配置对应的模型、数组和最新阶段报告。正式实验需要保留多次运行时，为每次运行设置不同的 `output_dir` 和 `report_dir`。

## 3. 部署依赖与版本规则

版本固定在 [requirements-deploy.txt](../requirements-deploy.txt)，共享 [训练约束](../configs/constraints-train.txt)。现有 yolo 已安装，无需重复移除或安装包。

新环境的训练依赖和 cu129 PyTorch 已恢复后，部署安装入口为：

```powershell
python -m pip install -r requirements-deploy.txt
python -m pip check
```

如果新环境从 tf2 克隆，须先按[安装记录第 10 节](环境安装记录.md#10-m0-05-统一训练与部署环境)处理其 TensorFlow/protobuf 冲突。TensorRT Windows 运行库约 2.1 GiB，来自 NVIDIA 官方索引；本机已经下载并核验的 wheel 缓存在 `tmp/deploy_wheels/`，仅是可重建的安装缓存。

ORT 1.19 CUDA 推理进程先导入 torch 加载 CUDA/cuDNN DLL，然后创建 CUDA provider session，并通过 profile 核实节点执行；CPU 回退不能通过 CUDA 验收。TensorRT 走直接 Python API，使用 torch GPU 内存和 stream，不运行 PyTorch 模型。当前环境并未验证 ORT 的 TensorRT EP。

TensorRT 11 engine 采用模型中的 FP32 类型，关闭 TF32；后续 FP16 需要按 [NVIDIA TensorRT 11 迁移指南](https://docs.nvidia.com/deeplearning/tensorrt/latest/api/migration/tensorrt-10x-to-11x.html)处理显式类型，不能照搬旧 `BuilderFlag.FP16` 写法。engine 绑定本次 TensorRT、Windows 与 GPU 环境，移机按 [NVIDIA 支持矩阵](https://docs.nvidia.com/deeplearning/tensorrt/latest/getting-started/support-matrix.html)重新构建和验收。
