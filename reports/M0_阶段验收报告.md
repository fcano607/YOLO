## 4. ONNX、ORT 与 TensorRT 原始输出对照

已实际导出、检查并运行原模型。参数为 batch1、640×640、FP32、opset17、dynamic=False、simplify=False、nms=False；ONNX full_check 通过，IR=8。输入 `images [1,3,640,640]`，输出为 `[1,116,8400]` 与 `[1,32,160,160]`，均 float32。116 = 4 个框坐标 + 80 个类别分数 + 32 个 mask 系数。

ONNX 约 11.2 MiB；原生 TensorRT engine 约 15.5 MiB，强类型 FP32、关闭 TF32，workspace 上限 1 GiB。模型和参考数组保留于 `artifacts/precheck/M0-05/`。

使用 bus 和桌面图，先保存同输入 PyTorch CUDA FP32 参考张量，再让各后端读取。判据预先固定：`abs(actual-reference) <= 0.001 + 0.0001 * abs(reference)`，并检查形状、float32 和 finite。

| 后端 | output0 最大绝对差，两图 | output1 最大绝对差，两图 | 超出联合容差元素 | 实际执行证据 |
| --- | ---: | ---: | ---: | --- |
| ORT CPU | 0.00225830 | 0.00001836 | 0 | profile 中 912 次 CPU 节点事件 |
| ORT CUDA | 0.00271606 | 0.00002015 | 0 | 530 次 CUDA 节点事件，无 CPU 节点事件 |
| TensorRT FP32 | 0.00207520 | 0.00001895 | 0 | engine 反序列化、GPU 地址执行 `execute_async_v3`、同步回读 |

大坐标的绝对差可大于 0.001，仍满足绝对与相对联合容差。profile 事件数不是网络层数或速度指标。[CPU 数值](../logs/deployment/M0-05_ort_cpu.json) · [CUDA 数值](../logs/deployment/M0-05_ort_cuda.json) · [TensorRT 数值](../logs/deployment/M0-05_trt.json) · [一致性汇总](../logs/deployment/M0-05_summary.json)

ORT / TensorRT 工作进程未导入 Ultralytics、未执行 PyTorch 模型。ORT CUDA 仍用 torch 加载 DLL，TensorRT 用 torch 分配 GPU 缓冲及 stream，尚未彻底去掉 torch。没有验证 ORT TensorRT EP。TensorRT 首次中文路径失败后，改为 Python 读取 ONNX bytes 再解析；失败日志保留。

当前证明的是后端运行与原始数值兼容，尚未实现完整独立 NMS、mask 重建 / 坐标还原、30 张固定图完整输出对齐、FP16、训练后模型部署及正式性能评价。
